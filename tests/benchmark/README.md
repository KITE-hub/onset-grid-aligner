# ドラム実音源ベンチマーク

このベンチマークでは、正解値を「音源の中央時点でグリッドに合わせるために必要な移動量」と定義します。`reference_delay_ms` は音源を実際に動かす量です。正の値は遅らせ、負の値は前へ動かします。中央でアタックがグリッドより +X ms 遅れていれば、正解の移動量は -X ms です。ドリフトが有意な推定では、中央時点に換算できる候補を曲長の50%地点へ移してから採点します。

音声ファイルはこのフォルダ以下に置き、`real_drums.json` に登録します。音声はGitに追加せず、ローカルまたは非公開CIアーティファクトとして管理できます。

各レコードの形式:

```json
{
  "audio": "audio/live_funk_01.wav",
  "source_id": "live_funk_01",
  "split": "calibration",
  "category": "acoustic",
  "genre": "funk",
  "bpm": 96.0,
  "reference_delay_ms": -7.5,
  "tolerance_ms": 3.0
}
```

`category` は `acoustic`、`electronic`、`hybrid` のいずれかです。ジャンル、テンポ、奏法、録音・分離条件に偏りが出ないよう複数曲を登録してください。生ドラムは、可能な限り同一曲について生録りと電子音の両方を揃えます。既存の全体音源バッチCSVはドラムステムの正解データとして登録しません。

推定器の選択に使う曲は`calibration`、最終評価用の曲は`holdout`に分け、同じ`source_id`を両方へ入れないでください。候補ごとの誤差と候補間の最大差をCIログへ出します。本番ではイベント包絡線系、スペクトル系、Wavelet系、高域帯域系をそれぞれ一群にまとめます。2群以上の代表値が6 ms以内で一致すれば`delay_status=consensus`として補正量を返し、1群のみなら`delay_status=provisional`として暫定値を返します。群間の差が大きい場合は`delay_status=ambiguous`として補正量を保留します。500–1500 Hzの別帯域と30–120 Hzのキック帯域は最終補正量の判定に使いません。6 msは初期の判定幅で、後から評価結果で調整できます。すべての候補値は「音源を動かす量」の符号で出し、正は遅らせる量、負は前へ動かす量です。

`reference_delay_ms` は解析結果から逆算せず、DAW上で設定した既知のオフセット、または独立に確認した中央時点のグリッド位相から記録します。人間演奏の微細な揺れを「誤差」と混同しないよう、基準グリッドと許容幅をレコードごとに決めてください。正解値の根拠と音源の利用条件は、音源と同じディレクトリのメタデータに残してください。

実行方法:

```text
python -m pip install -r requirements-dev.txt
python -m pytest -s
```

合成ドラムの回帰テストはCIで実行されます。実音源が未登録なら実ドラム評価はスキップされます。音源がない状態のCI成功は、実ドラムの精度を保証しません。CIに実音源を含める場合は、利用許諾のあるデータセットを安全に渡してください。
